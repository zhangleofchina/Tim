# WorkBuddy 链路验证

这个目录由 WorkBuddy 在本机生成并提交，用来验证 GitHub 通道是否可用。

## 实测结论（2026-10-30）

| 环节 | 结果 |
|---|---|
| 本地 git 提交 | 正常 |
| HTTPS 克隆 | 正常 |
| 推送到 GitHub | 正常，凭据已在系统钥匙串中，无需每次输密码 |
| 走本机代理推送 | 失败，返回 502 |
| 绕过代理推送 | 成功 |

## 关键坑：本机代理

本地运行环境注入了 `HTTP_PROXY=http://127.0.0.1:55036`，这个代理对 GitHub 的请求会返回 502，但 GitHub 直连其实是通的。

解决方式：只对 github.com 关闭代理，不影响其他服务。

```
git config --global http.https://github.com/.proxy ""
```

## 三个通道的能力边界

| 通道 | 读 | 写 | 依赖本机网络 |
|---|---|---|---|
| 本机 git（HTTPS） | 可 | 可 | 是，但需绕过代理 |
| GitHub 连接器（服务端） | 可 | 不可，当前授权是只读（403） | 否 |
| 浏览器网页登录 | 未验证 | 未验证 | 是 |
